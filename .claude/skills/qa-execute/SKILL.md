## タスク

QA 検証ステップを「事前表示 → 実行許可 → コマンド実行 → 確認手続き → 結果表示」の一連のフローで制御する。確認手続きのスキップ・省略は禁止。仕様書: `docs/specs/agentic/skills/qa-execute-skill.md`

## 入力

呼び出し元（`/qa` スキル）から以下の情報を受け取る:

| パラメータ | 必須 | 説明 |
|-----------|------|------|
| コマンド | Yes | 実行するコマンド文字列（CLI コマンドまたは MCP ツール呼び出し） |
| 期待結果 | Yes | このステップで期待する結果の説明 |
| 検証種別 | Yes | `ingest` / `delete` / `none` |
| 検証パラメータ | No | 共通検証フローに必要な追加情報（検索クエリ、source_type 等） |

## 処理手順

### 1. 事前表示

実行するコマンドとパラメータ、期待結果を表示する:

```
--- QA ステップ ---
コマンド: <実行するコマンド>
期待結果: <このステップで期待する結果>
検証: <共通検証フロー（取り込み後） / 共通検証フロー（削除後） / なし>
```

### 2. 実行許可

`AskUserQuestion` でユーザーに実行の許可を確認する:

```
実行しますか？ (y: 実行 / s: スキップ)
```

- `y` → ステップ 3 へ
- `s` → 結果を「SKIP」として記録し、ステップ 5 へ

**重要**: バッチ承認は不可。各ステップで必ず都度確認する。

### 3. コマンド実行

許可を得た後、コマンドを実行する。

エラーが発生した場合:

- エラー内容を表示する
- 結果を「NG」として記録する
- 検証フローは実行しない（実行自体が失敗しているため）
- ステップ 5 へ進む

### 4. 確認手続き

検証種別に応じて以下を実行する。**省略・簡略化は禁止**。

#### 検証種別: `ingest`（取り込み後の共通検証フロー）

以下を順に実行し、全ての結果を表示する:

1. **実データ確認**: source_store / converted_store のファイルを `ls` で確認
   - ファイルが存在すること
   - メタデータの確認:
     - **local 以外**（web, bluesky, zenn, youtube, aozora, journal）: `.meta` サイドカーファイルの内容を確認（source_type, title, collected_at）
     - **local**: metadata.db の sources テーブルで確認: `sqlite3 <source_store>/metadata.db "SELECT source_id, source_type, title, collected_at FROM sources WHERE source_type='local'"`

2. **Git 状態確認**: source_store 内の git リポジトリで `git status` を実行
   - 新規ファイルが追加されていること
   - 意図しない変更がないこと

3. **検索確認**: `search --query <取り込み内容に関連するクエリ>` で検索
   - 取り込んだソースがヒットすること
   - メタデータ行（Source, Title, Type, Section, Collected）が正しいこと

#### 検証種別: `delete`（削除後の逆方向検証）

1. **実データ確認**: source_store からファイルが削除されていること
2. **Git 状態確認**: ファイル削除が `git status` に反映されていること
3. **検索確認**: 削除したソースが検索結果に含まれないこと

#### 検証種別: `none`

確認手続きを行わない。コマンドの実行結果のみを表示する。

### 5. 結果表示

実行結果と検証結果を表示する:

```
--- 結果 ---
コマンド: <実行したコマンド>
実行結果: OK / NG / SKIP
検証結果: OK / NG / SKIP（検証なし）
詳細: <検証で確認した内容のサマリー、NG の場合は失敗箇所>
```

結果（OK / NG / SKIP）を呼び出し元に返す。

## 制約

- **都度確認**: 各ステップで必ず AskUserQuestion による実行許可を取得する。複数ステップのバッチ承認は不可
- **確認手続きのスキップ禁止**: 検証フローは省略・簡略化してはならない。「確認済みなのでスキップ」「出力が多いので省略」は禁止
- **事前表示の義務**: 実行前に必ずコマンド・パラメータ・期待結果を表示する
- **結果の全量表示**: 検証結果は省略せず全量表示する
